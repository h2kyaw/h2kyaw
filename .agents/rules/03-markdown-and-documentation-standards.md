# Markdown & Documentation Engineering Standards

- **GitHub Flavored Markdown (GFM)**: Use valid semantic markdown with clean headings hierarchy (`#`, `##`, `###`), tables, and standard list formatting.
- **File Naming Convention**: Use lowercase kebab-case for all documentation and note filenames (e.g., `git-cheatsheet.md`, `project-portfolio.md`).
- **Relative Path Consistency**: When cross-referencing files inside the repository, always use relative Markdown links with valid file targets.
- **Code Fencing**: Always specify syntax highlighting languages for code fences (e.g. ````bash````, ````yaml````, ````markdown````).
- **Conciseness & Scannability**: Use tables, callouts, and bullet points to ensure rapid readability.
